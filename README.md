# TaskFlow API

> An evolving backend project built with **Node.js + TypeScript**, designed to demonstrate practical application of advanced TypeScript and progressive software architecture.

TaskFlow is not a tutorial project or a finished CRUD application.

It is an **evolving engineering playground** where the codebase grows in complexity as new requirements appear, allowing architecture, type-safety, testing and design decisions to evolve naturally.

## 🎯 Goals

- Build a production-oriented REST API.
- Apply advanced TypeScript concepts in real scenarios.
- Evolve from simple implementations toward maintainable architecture.
- Make deliberate engineering decisions instead of introducing premature abstractions.
- Document architectural trade-offs and technical decisions.

## 🛠️ Stack

- **Node.js**
- **TypeScript**
- **Fastify**
- **pnpm**
- **Vitest**
- **PostgreSQL** _(planned)_
- **Prisma** _(planned)_
- **Zod** _(planned)_

## 🧭 Evolution

The project will progressively introduce:

```text
Simple API
    ↓
Domain modeling
    ↓
Type-safe abstractions
    ↓
Validation & error handling
    ↓
Testing
    ↓
Persistence
    ↓
Architecture
    ↓
Production-ready backend
```

The goal is not to maximize complexity, but to introduce it **only when the project has a reason to need it**.

## 📚 Learning Philosophy

TaskFlow evolves alongside my TypeScript knowledge.

Concepts such as:

- Generics
- `keyof`
- Indexed Access Types
- Mapped Types
- Conditional Types
- `infer`
- Type-safe APIs
- Runtime validation

will be introduced when they solve an actual problem in the application.

> **Learn the concept. Apply it. Challenge the implementation. Refactor it.**
